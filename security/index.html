Local-first boundary

Security boundary

A private corpus should remain private by default.

The public site explains and demonstrates the product. The canonical working instrument is designed to process real investigations on the user’s own device.

Public demo Local application Original evidence Model boundary Exports

The public demo requests no private files

The sample investigation is a deterministic, fictional corpus checked into the site. It makes no analysis request to an external model and does not ask a visitor to select or upload documents. Its purpose is to demonstrate the event-to-evidence relationship honestly.

Real corpora belong in the local application

The intended desktop application inventories and processes investigation files on the user’s computer. Local processing is important for unpublished reporting, whistleblower material, legal discovery, proprietary documents, personal archives, and other sensitive collections.

“Local-first” does not mean “risk-free.” The application still needs clear file permissions, scoped sidecar capabilities, encrypted-device guidance, explicit export destinations, and reproducible update and rollback procedures.

Original evidence remains immutable

Source bytes are preserved separately from extracted text, thumbnails, normalized metadata, timeline events, and model output. Reprocessing creates a new run and new receipts rather than silently replacing the previous result.

OriginalsRead-only source bytes retained under stable identifiers.
Derived artifactsExtracted text, previews, normalized dates, and indexes stored separately.
Review receiptsAppend-only records of human confirmation, dispute, rejection, or correction.
Integrity hashesByte-identity checks that support preservation but do not independently prove authorship or truth.

Remote inference is opt-in and bounded

The core evidence model must work without turning the corpus into an opaque provider upload. Any optional model operation should disclose exactly what material leaves the device, why it is needed, which provider receives it, and what record of that operation is retained.

Model output may propose assertions, links, or classifications. It may not mutate originals or silently promote inference into observed fact.

Exports can contain sensitive evidence

Reports, source packages, and project backups may contain confidential material even when the application itself is local. Export workflows should support redaction, public-safe subsets, manifest inspection, and clear warnings before a bundle leaves the device.

The safest public demonstration is one that proves the product without asking a stranger to trust an unexplained upload box.
