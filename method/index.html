Method

Evidence stays beneath every conclusion.

ChronosAudit treats the timeline as a derived projection. The authority remains in preserved source bytes, exact locations, recorded assertions, and the transformations that connect them.

Authority model Temporal evidence Processing pipeline Contradictions Portable outputs

Authority model

timeline event → extracted claim → exact source passage → original file → file hash / provenance record

A timeline event is not the underlying truth. It is a projection built from one or more temporal assertions. Each assertion points to a precise location in a source asset and records how its date was observed, normalized, or inferred.

Source assetThe preserved original file and its integrity, format, metadata, and import record.
Source locationThe page, line, byte range, message field, or other exact location that supports a claim.
Temporal assertionA dated claim extracted from a source, with evidence type, precision, method, confidence, and review status.
Event clusterA derived grouping of related assertions presented on the working timeline.
Processing runA receipt describing the tool version, settings, inputs, outputs, and time of a transformation.

Temporal evidence remains typed

ChronosAudit does not flatten every date into one chronology without qualification. Filesystem timestamps, embedded metadata, email headers, dates stated in text, relative references, machine-inferred dates, conflicts, and unresolved expressions remain distinguishable in both the data model and the interface.

Observation and inference

An email header that states a sent time is an observation about the message record. Resolving “last Tuesday” against that header is a normalization step. Guessing that a meeting probably occurred before a document was edited is an inference. Those are not equivalent and should not be styled or stored as if they were.

Processing pipeline

1. Preserve

Inventory source files, retain original bytes, record format and metadata, and compute integrity hashes. Hashing confirms byte identity; it does not establish authorship, truth, or custody by itself.

2. Extract

Use format-specific adapters to recover text, metadata, headers, and explicit source locations. Every adapter records its version and warnings rather than silently dropping unsupported material.

3. Normalize

Represent dates as points, ranges, partial dates, relative references, or unresolved expressions. Preserve the raw expression beside the normalized value.

4. Reconstruct

Cluster compatible assertions into candidate events, compare document versions, and identify missing or changed obligations, claims, and dates.

5. Review

Allow a human reviewer to confirm, dispute, reject, or correct derived assertions while preserving an append-only receipt of the decision.

Contradictions are shown, not “fixed”

When two records disagree, ChronosAudit links them in a contradiction object and presents both claims with their support. It does not silently choose a winner or rewrite the chronology into a smooth narrative. Resolution can be recorded, but the original conflict remains inspectable.

Portable outputs

A completed investigation should export a readable report, a structured manifest, an evidence index, and processing receipts. The report must remain useful without a live service, and its links must resolve against the exported source package or clearly identify unavailable material.
